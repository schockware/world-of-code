# ENC-OPM209: M-209 Army operator (core)

Covers `m209-army`, the US Army text conventions for the `m209` converter, from TM 11-380 as quoted by Bouchaudy, and from Blair and the `m209` library (`../../../docs/operators.md`, section 3).

## Requirements

### ENC-OPM209-001
**Status:** Draft
**Level:** MUST
`m209-army` MUST use Z as its separator letter, with a maximum gap of 2, and its `separator` value MUST be `z`.
**Rationale:** *Machine and cribs.* The converter "was originally designed to encipher one Z between each word so that the deciphered text would appear on the tape in word lengths". The machine printed Z as a space. One Z per space made word lengths visible and Z the most frequent letter, so TM 11-380 (1947) ordered the spacing varied on every message: omit some Zs, double others, and "NEVER USE MORE THAN TWO Z'S BETWEEN WORDS".
**Contract:** `operator-id.json`, `message.json`
**Vectors:** `opm209.json#attack-at-dawn`, `opm209.json#mission-accomplished`, `opm209.json#spacing-variation-1947`, `opm209.json#reject-three-z`

### ENC-OPM209-002
**Status:** Draft
**Level:** MUST
`m209-army` MUST spell digits as ZERO ONE TWO THREE FOUR FIVE SIX SEVEN EIGHT NINE.
**Rationale:** *Alphabet.* Numbers were spelled out. The exact words were not found in the sources read, so these are a project choice pending TM 11-380.
**Contract:** None. This is behavior.
**Vectors:** `opm209.json#english-digits`

### ENC-OPM209-003
**Status:** Draft
**Level:** MUST
`m209-army` MUST render `.` as X, and support no other marks.
**Rationale:** *Alphabet.* The Blair example message uses X between sentences, with Z spacing around it (`ACCOMPLISHEDZXZALL`). Rules for other marks were not found.
**Contract:** None. This is behavior.
**Vectors:** `opm209.json#full-stop-is-x`, `opm209.json#mission-accomplished`, `opm209.json#reject-comma`

### ENC-OPM209-004
**Status:** Draft
**Level:** MUST
`encoded` longer than 500 letters MUST be rejected with reason `operator.too-long`.
**Rationale:** *Cribs and depth.* "Messages exceeding 100 groups in length must be divided into two or more approximately equal parts so that no parts exceed 100 groups [500 letters]." (TM 11-380, 1947). Long messages give the statistical attacks more to work with.
**Contract:** None. This is behavior.
**Vectors:** `opm209.json#accept-500-letters`, `opm209.json#reject-501-letters`

## Notes

- **Edition.** The spacing variation and the 500-letter limit are quoted from the 1947 manual, written after TICOM found that the Germans had read more than 10% of M-209 traffic. Whether WWII operators followed them is not confirmed. A strict WWII operator would use gap 1 everywhere, which this operator also accepts.
- **The variation is the caller's choice.** The 1947 manual also says never to use "a disproportionate number of any one of the variations" or "characteristic points" for them. That is judgment about patterns, so it cannot be a requirement of `prepare`.
- **Reading Z back** is the decoding problem described in `../m209.md`: the reader decides which Zs were spaces.
- **Padding** (the `m209` library's X to fill the last five-letter group) is display, and is not modeled.

## Population assumptions

This spec assumes the caller or population handles the following.

- **Spacing variation.** Choosing 0, 1 or 2 Zs per gap without a pattern, when following the 1947 rules.
- **Single letters.** Spelling them as phonetic words, before they become tokens.
- **Splitting.** Messages over 500 letters split into parts, each with a new indicator.
