# M-209 (US Army Converter M-209, Hagelin C-38 derived): research notes

Research date: 2026-09-29. "Verified" means the URL was opened (fetched, or returned as a search result whose text was read) in this session and the stated facts were read from it. ## 1. History

- Designed by Boris Hagelin (Sweden, AB Cryptoteknik) as a development of his earlier C-36; the manufacturer's designation is C-38. The US Navy called it CSP-1500. Manufactured in the US by Smith-Corona (Groton and Syracuse, New York) from 1942, at about 400 units per day, over 140,000 units in total; it stayed in use through the Korean War. (Wikipedia, verified; Crypto Museum, verified.)
- Crypto Museum states Hagelin sold the US rights for US$ 8,614,790 (verified, via fetch summary; re-check before quoting).
- Tactical, portable, hand-cranked, 178 x 140 x 83 mm, about 2.7 kg. (Wikipedia and Crypto Museum, verified.)
- The Barker book text describes a "Model Type C-48" with "54 movable lugs, two lugs on each of 27 lug-bars" (Internet Archive text, verified via fetch summary). One blog (chris-intel-corner) claims the C-38 had 29 bars rather than 27; nothing else corroborated this and it was not used.

## 2. Mechanism (what computes the key stream)

There are three cooperating parts, plus an input/print stage.

1. Six key wheels, left to right carrying 26, 25, 23, 21, 19 and 17 letters, each with one pin per letter. Each pin is slid left (ineffective) or right (effective). Total pins 26+25+23+21+19+17 = 131. Per cycle every wheel advances exactly one letter. (Wikipedia, Blair ch. 3, virtualcolossus tutorial, all verified.)
2. One pin per wheel is "in play" (aligned with the wheel's guide arm) at any moment. When the letters `AAAAAA` are displayed, the pins in play are those of the letters `PONMLK` (wheel 1 to wheel 6). More generally the in-play pin is a fixed number of letters ahead of the displayed letter on that wheel (Wikipedia, verified; I reproduced the offsets, see below).
3. A cage of 27 bars, each with two movable lugs. A lug can sit in one of 8 fixed slots: 6 "active" slots (1 to 6, meaning "opposite wheel n's guide arm") and 2 "neutral" slots (0). During a cycle the cage turns once. Each bar with at least one lug opposite a guide arm that is pushed out by an effective pin is displaced to the left. The number of displaced bars, 0 to 27, is the shift K for this letter. (Wikipedia, Blair ch. 3, virtualcolossus, all verified.)

Per-letter procedure (as reproduced by my simulator against four published 26-letter checks, see the wiring-data file):

1. For each wheel n, look at its in-play pin. Wheel n is "active" if that pin is effective.
2. A bar is displaced if either of its lugs is set to a wheel n (1 to 6) that is active. A lug in a neutral slot never displaces. Count displaced bars: K in 0..27. Bar order in the cage is irrelevant to K (the count is all that matters).
3. Print the letter C from the plaintext letter P and K (see section 3).
4. Every wheel advances one step: the displayed letter becomes the next letter in that wheel's own alphabet (wrapping). The letter counter increments.

The order of steps 3 and 4 does not matter to the result; K is computed from the wheel positions before the advance.

Nothing else is stateful. In particular there is no carry between wheels (unlike Enigma rotors), which is why the key stream has period exactly the product of the wheel sizes (section 5).

## 3. The output stage: what "C = K - P" means exactly

Sources say the machine is a reciprocal (Beaufort-type) substitution whose alphabets are the reverse of the plaintext alphabet (`ZYXWVUTSRQPONMLKJIHGFEDCBA` against `ABCDEFGHIJKLMNOPQRSTUVWXYZ`), rotated by K places (Wikipedia and Blair ch. 1, verified: "the reciprocal of the plaintext alphabet ... rotated by 0-27 places").

Tested against published check vectors with A=0 ... Z=25:

    C = (K - 1 - P) mod 26        equivalently        C = (K + (25 - P)) mod 26

All four published 26-letter checks (which encipher `A` 26 times) match this exactly, and no other offset does. Consequences:

- The README's `C = K - P` is correct only with a numbering offset: plaintext letters numbered A=1 ... Z=26, ciphertext letters numbered A=0 ... Z=25. With A=0 for both alphabets the formula is `K - P - 1`. A future spec must state the numbering explicitly.
- With K=0 and P=A the ciphertext is Z, not A.
- K ranges 0 to 27 but the alphabet has 26 letters, so K=26 and K=27 act as K=0 and K=1. The key stream is therefore not uniform on 0..25 even when bars are random; this is one of the statistical biases that attacks exploit.
- Reciprocity: applying the same formula to C with the same K returns P. So encrypting and decrypting are the same operation on the same key stream.
- A letter can encipher to itself: C = P exactly when K = 2P + 1 (mod 26), which needs K odd. This differs from Enigma, where a letter never encrypts to itself. (Derived algebraically from the formula above.)

### The C/D (encipher/decipher) switch

The switch changes only the printing, not the key stream (virtualcolossus tutorial, Blair's M-209-B page, verified):

- Encipher (C): the machine prints ciphertext on the tape automatically spaced into groups of five letters.
- Decipher (D): the tape is printed without grouping, and a deciphered `Z` is printed as a space.
- The knob/printwheel alphabets are reciprocal, so the letter entry and the wheel movements are otherwise identical in both modes.

Consequence for decryption: any real `Z` in a plaintext (for example in "PIZZA") is printed as a space, so `PIZZA` decrypts as `PI  A`. This is visible in the m209 library's own tutorial output (`THE PI  A HAS ARRIVED ...`, verified).

## 4. Key structure

A daily "key list" (a table published for a set of days/net; Blair's collection uses two-letter identifiers `AA` to `ZZ`, 676 tables) contains:

1. Pin settings: for each wheel, the set of letters whose pin is effective (right). In a printed table this is a grid of 26 rows by 6 columns showing a letter where the pin is effective and a dash where it is not.
2. Lug settings: 27 bars, each written as a pair `a-b` with a, b in 0..6 (0 = neutral), for example `1-0`, `0-3`, `3-4`. Bars are written in a normalized order (the printed tables list the pair with the neutral lug on a fixed side, for instance `1-0`, `2-0`, `0-3`, `0-4`). The order of the 27 bars is irrelevant to the output.
3. A "26-letter check": the ciphertext from enciphering `A` 26 times with all wheels at `A` and the letter counter at 0000, used to verify that pins and lugs were entered correctly (Blair ch. 3, key table FM, verified).

Per-message (not in the key list):

4. Six start positions ("message indicator"): the six wheel letters at the start of the message.
5. A system indicator: one random letter used to derive the internal indicator.

Wheel start letters can only be letters that exist on that wheel (section 6 below and the wiring-data file).

## 5. Keyspace arithmetic

All numbers below were computed with exact integer arithmetic.

Period of the key stream (the machine's cycle):

    26 x 25 = 650
    650 x 23 = 14,950
    14,950 x 21 = 313,950
    313,950 x 19 = 5,965,050
    5,965,050 x 17 = 101,405,850

The README figure 101,405,850 is correct. The six moduli are pairwise coprime: 26 = 2 x 13, 25 = 5^2, 23 (prime), 21 = 3 x 7, 19 (prime), 17 (prime); all 15 pairs have gcd 1. Hence lcm = product = 101,405,850, so the key stream is exactly periodic with that period and the wheels realign only after that many letters. (Wikipedia states the same period, verified.)

Pins: 131 binary pins, 2^131 = 2,722,258,935,367,507,707,706,996,859,454,145,691,648 (about 2.72 x 10^39).

Lugs, three ways of counting:

- Physical placements: each bar has 2 indistinguishable lugs in 2 distinct slots of 8, C(8,2) = 28 per bar. Over 27 distinguishable bars that is 28^27 = about 1.18 x 10^39 (2^129.8).
- Functional types per bar: with slot symbols 0 (either neutral slot) and wheels 1 to 6, an unordered pair gives 1 (0,0) + 6 (wheel, 0) + C(6,2) = 15 (two different wheels) = 22 distinct effects. The (0,0) bar is inert. Assumes two lugs can never be set to the same wheel (Rijmenants/virtualcolossus and the m209 library treat the pair as two different wheels or a neutral slot; see ambiguities).
- Because the cage produces only a count, bar order does not matter: the number of distinct drum settings by effect is the number of multisets of size 27 from 22 types, C(27 + 21, 21) = C(48, 21) = 22,314,239,266,528 (about 2^44.34).

Pins and lugs together (by effect): 2^131 x C(48,21) = 60,745,137,229,234,349,349,747,164,213,839,675,460,848,318,775,558,144 (about 6.07 x 10^52, 2^175.34). Multiplying by the 101,405,850 start positions gives about 6.16 x 10^60 (2^201.94).

These are upper bounds on distinct keys: many pin/lug combinations are equivalent (pins on a wheel that no lug references do nothing, the mod-26 aliasing of K, and so on). I did not compute the equivalence-class count. A blog page (chris-intel-corner, verified but low authority) quotes "2^174" without derivation; the closest figure from my arithmetic is 2^175.34, so treat the blog's value as unexplained, not as a correction. The README's "huge keyspace" is right; give the pin (2^131) and lug counts above rather than a single number.

## 6. Operating procedure and message indicators (US Army style)

Sources: Blair's "Practical Use of the M-209" chapters 3 and 4 (verified), m209 library docs and source (verified), a US training film TF 11-1400 cited in that library's source (unverified; not seen). TM 11-380 (the manual) is listed by Crypto Museum and Blair but was not opened.

Sender:

1. Choose a key list (two-letter key list indicator, e.g. FM), an external message indicator (six letters, one per wheel, each valid for its wheel; never reuse one with the same key list), and a system indicator (one letter).
2. Set the wheels to the external indicator, letter counter to 0000, switch to C. Encipher the system indicator letter twelve times. Tear off the tape (12 letters).
3. Reset the counter to 0000. Set the wheels from the tape, left to right: wheel 1 takes the first letter; for each further wheel take the next tape letter; a letter that does not exist on the wheel being set is crossed out and the next tape letter is tried. This gives the internal message indicator. If the 12 letters run out, restart with a different external and system indicator. (Blair ch. 4, verified.)
4. Encipher the message. Spaces are entered as `Z`. Numbers are spelled out; single letters are spelled with phonetic words (virtualcolossus tutorial and Blair's M-209-B page, verified).
5. Transmit: first group = system indicator letter twice + first three letters of the external indicator; second group = last three letters of the external indicator + the two-letter key list indicator; then the ciphertext groups; then the same two indicator groups again. The example in Blair ch. 4 is `GGABC DEFFM [cipher] GGABC DEFFM` (verified).

Worked indicator example printed in Blair ch. 4 (verified): tape `FPKFW MHUPL CD` gives wheels 1 to 4 = F, P, K, F; `W` is not on wheel 5 (letters A to S), so `M` is used; wheel 6 = H; internal indicator `FPKFMH`. My simulator reproduces this tape exactly from the FM key with external `ABCDEF` and system letter `G` (see the wiring-data file).

The m209 library enciphers the system letter 24 times instead of 12, noting that 12 is occasionally not enough letters. Under a uniform-random model of the tape, the chance that 12 letters cannot fill all six wheels is about 0.40% (I computed this; the real tape is not uniform, so it is an estimate).

Receiver: read the indicators from the first two groups, set the wheels and derive the same internal indicator, then decipher in D mode (no grouping, `Z` printed as space).

## 7. Quirks worth preserving in a faithful implementation

- K in 0..27 folded to a 26-letter alphabet (aliasing of 26 and 27).
- The A=1 (plaintext) / A=0 (ciphertext) offset in "C = K - P".
- Self-encipherment is possible.
- `Z` is the space marker on input and prints as a space only in D mode; real `Z`s are lost in decryption.
- Wheel alphabets are not all A to Z: wheels 2 and 3 skip letters (wiring-data file), so start positions and the internal-indicator skipping rule depend on it.
- Group of five: added by the machine in C mode, and the last group may be padded (see ambiguities).
- Only letters are enciphered. No digits, punctuation, or case.
- The sensed pin is offset from the displayed letter, so "wheel set to A" does not mean "pin A is in play".

## 8. Cryptanalysis history

Verified facts and citations are in the References. Precisely:

- Depth (several messages with the same settings) was the practical weakness: by early 1943 German codebreaking could read an estimated 10 to 30 percent of M-209 traffic (Wikipedia, verified); Crypto Museum says that, with messages in depth, German cryptanalysts could break them in about four hours (verified via fetch summary; the sentence is Crypto Museum's own summary, not checked against a primary source). "In depth" means same key list and the same message indicator. The procedure's rule "never use a particular external message indicator more than once with a single key table" (Blair ch. 4, verified) exists to prevent this.
- Known plaintext / probable word: W. G. Barker, "Cryptanalysis of the Hagelin Cryptograph", Aegean Park Press, Laguna Hills CA, 1977 (Cryptographic Series no. 17). Text opened on the Internet Archive; it works back from known plaintext to recover the key, and includes problem sets; it does not contain one complete end-to-end key-and-ciphertext example (verified).
- Ciphertext-only, Bell Labs, 1970s: J. Reeds, D. Ritchie and R. Morris, "The Hagelin Cipher Machine (M-209): Cryptanalysis from Ciphertext Alone", unpublished technical memorandum, Bell Laboratories, 1978 (bibliographic details from search results; body not opened). Wikipedia and Crypto Museum both describe a 1970s ciphertext-only attack by Ritchie, Reeds and Morris that could solve messages of at least about 2,000 to 2,500 letters, which the authors did not publish (Crypto Museum's exact wording; verified).
- R. H. Morris, "The Hagelin Cipher Machine (M-209): Reconstruction of the Internal Settings", Cryptologia 2(3), 1978, pp. 267 to 289 (bibliographic details from search results; paper body not opened). The README calls this "Morris 1978"; this is the published Cryptologia paper, distinct from the unpublished memo above. What exactly it requires (known plaintext amount) was not read.
- Modern hill climbing: G. Lasry, N. Kopal and A. Wacker, "Ciphertext-only cryptanalysis of Hagelin M-209 pins and lugs", Cryptologia 40(2), 2016, pp. 141 to 176. From the search-result summary: a four-stage hill-climbing plus simulated-annealing algorithm, first two stages after Geoff Sullivan's divide-and-conquer approach, recovering full pin and lug settings from ciphertext only with as few as 500 letters, versus a prior minimum of 750 to 1,250 letters; used to solve the final exercises in Barker's book and a public M-209 challenge. Also G. Lasry, N. Kopal and A. Wacker, "Ciphertext-only cryptanalysis of short Hagelin M-209 ciphertexts", Cryptologia 42(6), 2018 (cited by Wikipedia; venue and volume seen in a search listing; abstract not read), and an "Automated known-plaintext cryptanalysis of short Hagelin M-209 messages" paper by the same authors (title seen only; year and venue unverified).
- Magnus Ekhall, "A WW2 device for breaking the M-209 encryption machine", HistoCrypt (paper title and link only; the PDF could not be text-extracted, unverified).

Correction to a README statement: it says "recover the settings from a few thousand letters" via "known-plaintext or depth attacks (Barker, Morris)". Safer: Barker is known-plaintext or depth, the Reeds/Ritchie/Morris memo is ciphertext-only at roughly 2,000 to 2,500 letters, and modern hill climbing (Lasry, Kopal, Wacker) reaches ciphertext-only recovery from about 500 letters. A "few thousand" is right only for the 1970s ciphertext-only figure.

Why the key stream is attackable, in outline (standard view, not separately sourced here): K is a sum of independent-looking wheel contributions (each bar fires if a wheel it references is active), so each wheel's effective/ineffective bit sequence repeats with a short period (17 to 26), the K histogram is skewed, and statistical tests on the ciphertext against a language model can be split by wheel. The cited papers are the primary sources for this.

## 9. Ambiguities a spec must pin down

1. Numbering: state exactly `C = (K - 1 - P) mod 26` with A=0 or the equivalent with A=1 for plaintext and A=0 for ciphertext. The README's `C = K - P` is ambiguous.
2. Pin encoding: as the set of effective letters per wheel (the form used by the printed key lists and the check vectors), or as a bit string of length 26/25/23/21/19/17 in wheel-letter order. The letters, not positions, are canonical in sources.
3. Wheel alphabets: wheels 2 and 3 skip letters (wiring-data file). Position n on a wheel means the n-th letter of that wheel's own alphabet, not the alphabet position.
4. Sensed-pin offset: `PONMLK` when `AAAAAA` is displayed. Must be stated as an offset (15, 14, 13, 12, 11, 10 letters ahead in each wheel's own alphabet), not as "the pin under the displayed letter".
5. Advance direction: displayed letter moves to the next letter of the wheel's alphabet. (Inferred from data: the check vectors reproduce only with this direction.)
6. Lug encoding: two values 0..6 per bar, 0 neutral; whether `a-b` with a = b nonzero is allowed (physically it means both lugs against one wheel; sources said "both lugs may not be set against the same wheel", from a search-result summary, not the page text); whether order in the pair matters (it does not to the output); whether fewer than 27 bars are permitted (the m209 library fills the remainder with neutral bars).
7. Indicator derivation: how many letters (12 in the film/Blair, 24 in the m209 library), what to do when the tape runs out, and whether a mismatched-wheel letter is skipped or the process is restarted.
8. `Z` rule: input `Z` for space; on output D mode prints space for `Z`. Whether a decryption spec keeps `Z` or maps to space, and what to do with a real `Z`.
9. Group size: 5; whether the final group is padded and with what (the m209 library pads with `X` in the ciphertext, which decrypt to arbitrary plaintext letters; the procedural source for this was not read). The Blair decrypt example ends in `...ORDERSO`, the extra `O` being a padding artifact.
10. Letter counter: what it counts (letters enciphered, including Z), its width (`0000` shown), and whether it wraps; and whether it is part of the spec at all or only a machine feature.
11. Whether the spec models the whole procedure (indicators, groups, headers) or only the converter. The check vectors need only the converter.
